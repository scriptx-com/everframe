# @everframe/metro

`withEverframe(config, { projectRoot, dev })` preserves the existing Metro
configuration and adds a synchronous identity polyfill for Android and iOS.
It generates a build ID and writes `.everframe/<buildId>/manifest.partial.json`
with an `identity.js` polyfill. The polyfill sets `globalThis.__EVERFRAME_BUILD__`
before application modules execute.

Each platform has its own ID and bundle name: `index.android.bundle` on Android,
`main.jsbundle` on iOS. Native version, release labels and OTA provider update IDs
must not replace this bundle identity. Set `enabled: false` when the corresponding
SDK is excluded from a build.

Use one isolated staging directory for each build job. Metro stages both platforms
at configuration time. Collection reads the generated identity from the composed
map, checks the staged partial and compiled build ID, and promotes that completed
build to `latest-<platform>.json`. A later configuration load before collection is
safe; do not run another Metro invocation between collection and upload. Retain matching bytecode and maps;
reusing a build ID with different generated bytes is not a new release.

After the Hermes compiler has emitted bytecode and its composed map:

```sh
npx everframe build collect --staging .everframe --platform android \
  --bundle path/to/index.android.bundle \
  --source-map path/to/index.android.bundle.map
npx everframe build verify --staging .everframe --platform android --release
npx everframe sourcemaps upload-hermes --manifest .everframe \
  --platform android --app-id "$EVERFRAME_APP_ID"
```

Provide the scoped `EVERFRAME_API_TOKEN` only to the build/upload process. See the
[Expo Updates guide](../expo/README.md) for export and loaded-bundle identity.
